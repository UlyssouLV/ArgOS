> Issue parente : #152

# V1.0.0 — Refonte graphique totale de l’interface et Conservation en jours

## Problem Statement

Jusqu’à la 0.9.x, le Site couvre connexion, Administration, Live, enregistrement / relecture et calage horaire des Caméras, mais son interface a été empilée version après version : barre d’onglets en haut, thème clair par défaut du navigateur, police système, Réglages de la Caméra dépliés dans une ligne du tableau, Détection en section sous la liste, Relecture intégrée à la page Enregistrement, messages en texte brut, « Chargement… » partout. Aucune identité visuelle ; le logo ArgOS n’apparaît nulle part dans le produit.

Par ailleurs, la Conservation est bornée à 1–24 h : impossible de garder une semaine d’enregistrements, alors que c’est le besoin courant d’une vidéosurveillance domestique. Et la Timeline de la Relecture couvre toute la Conservation d’un bloc, ce qui ne tiendrait pas sur plusieurs jours.

## Solution

Remplacer toute l’UI par une interface **entièrement redessinée**, à l’identité unique, validée sur maquette au grilling, sous les **mêmes capacités produit** ; et porter la Conservation de **1 h à 30 jours**, avec une Relecture **un jour à la fois**.

### Identité visuelle (validée)

- **Thème sombre seul.** Fond `#0e0f12`, cartes `#16171b`, surfaces `#1e2025`, bordures `#2a2d34`, texte `#f2f2f3`, texte discret `#9b9ea8`.
- **Rouge de marque** `#c8102e` (celui du logo) en accent **ponctuel** : entrée active du rail (liseré + icône), anneau de focus, logo, pastille « DIRECT ».
- **Boutons** : principal clair sur sombre (`#f2f2f3` / texte `#111214`), secondaire en contour, fantôme pour les icônes.
- **Danger** : rouge orangé `#f0603c` (erreurs, Hors ligne, suppression), toujours avec icône + texte ; suppression confirmée par une boîte de dialogue. **Succès** `#3fb968`. **Inconnu** `#7d808a`.
- **États de Caméra** jamais par la couleur seule : pastille + libellé (« En ligne », « Hors ligne », « Inconnu » ; même règle pour les états de Mise à l’heure).
- **Polices** embarquées dans le build web (pas d’Internet requis) : **Inter** (UI), **JetBrains Mono** (heures, débits, adresses IP / MAC). Échelle : 12 / 13 / 14 (corps) / 16 / 20 (titre de page) / 24 (chiffres clés). Rayon 10 px (cartes), 8 px (contrôles).
- **Logo** : `docs/img/readme-banniere.jpg` détouré (blanc, œil rouge, fond transparent) en deux assets — logo complet (Connexion) et tête dans son viseur (rail, favicon). Remplaçable par une source vectorielle sans autre changement.

### Gabarit

- **Coquille** : rail latéral fixe 240 px, replié en icônes (64 px) sous 1024 px. Haut : tête du logo + « ArgOS ». Entrées : **Live** · **Enregistrement** (pastille « Place libre sous le seuil ») · **Relecture** · groupe **Administration** : **Caméras**, **Heure du Site**. Bas : Administrateur, bouton icône « Déconnexion », version d’ArgOS. Zone de contenu : en-tête de page collant (titre, surtitre « Administration » pour ses pages, actions de page à droite).
- **Écrans** : poste fixe et tablette (≥ 768 px). Téléphone : Plus tard.
- **Connexion** : logo complet, carte « Connexion au Site » (Identifiant, Mot de passe, Se connecter), erreur en alerte, pied « ArgOS <version> ».
- **Live** (page d’accueil, `/live`) : vidéo 16:9 sur toute la zone, fond noir. Barre fine : nom de la Caméra, état, codec, position « n / N », **Précédente** / **Suivante**, raccourcis ← / →. Flux indisponible / connexion : message dans la vidéo.
- **Caméras** (`/administration/cameras`) : bouton « Détecter des Caméras » en tête ; tableau Nom / Adresse / État / Flux / Enregistrement / « Réglages ». **Réglages de la Caméra** dans un **panneau latéral droit** (« Réglages de <nom> ») à sections repliables : Général (nom, adresse, Caméra active, enregistrement), Image, Encodage, Incrustation, ONVIF ; « Supprimer la Caméra » en bas ; Annuler / Appliquer en pied. **Détection** dans une **boîte de dialogue** large, onglets Candidats / Déjà configurées, ajout depuis un Candidat dedans.
- **Enregistrement** (`/enregistrement`) : alerte sous le seuil ; cartes chiffres Place libre (jauge + repère du seuil), Débit d’écriture, Conservation (avec la tenue) ; carte **Réglages** (Conservation en jours + heures, Seuil de place disque) ; tableau des Caméras, une ligne ouvre sa Relecture.
- **Relecture** (`/relecture/<caméra>`, entrée du rail) : en-tête avec liste de Caméras, état, sélecteur de jour ‹ jour › ; vidéo ; lecture / pause, instant lu, vitesses ×1…×16 en contrôle segmenté ; **Timeline d’enregistrement d’une journée** (00h → 24h, heure du Site), rappel de la fenêtre de Conservation. `/relecture` seule ouvre la dernière Caméra relue (navigateur), sinon la première.
- **Heure du Site** (`/administration/heure-du-site`) : carte Réglage (Source, Fuseau, Heure du Site, Enregistrer) ; « Vérifier maintenant » en tête ; tableau des Caméras (Mise à l’heure, dérive, écart, dernière).
- **États** : chargement en squelettes ; état vide = icône + phrase + action utile (« Aucune Caméra » → Détecter des Caméras) ; résultat d’une action en **toast** (bas à droite, rôle `status`) ; erreur de saisie à côté du champ. Titre d’onglet « <Page> · ArgOS ».

### Conservation en jours

- Bornes **1 h – 30 jours** (720 h). Saisie : deux champs **jours** + **heures**, validés ensemble. Affichage « 7 j », « 2 j 6 h », « 12 h ». Stockage inchangé en heures.
- La Relecture lit les Segments d’**un jour** (heure du Site) ; jours hors Conservation non sélectionnables.

## User Stories

### Identité et navigation

1. En tant qu’Administrateur, je veux une interface sombre, cohérente d’une page à l’autre et marquée du logo ArgOS, pour un produit qui a l’air fini.
2. En tant qu’Administrateur, je veux un rail latéral qui montre toujours où je suis et me mène en un clic au Live, à l’Enregistrement, à la Relecture, aux Caméras et à l’Heure du Site.
3. En tant qu’Administrateur, je veux arriver sur le Live après la connexion, parce que c’est ce que je regarde le plus.
4. En tant qu’Administrateur, je veux lire la version d’ArgOS sur l’écran de connexion et en bas du rail.
5. En tant qu’Administrateur sur tablette, je veux que le rail se replie en icônes pour laisser la place au contenu.
6. En tant qu’Administrateur, je veux que l’onglet du navigateur dise la page ouverte (« Caméras · ArgOS ») et porte l’icône ArgOS.

### Live

7. En tant qu’Administrateur, je veux une vidéo qui occupe tout l’écran disponible, avec le nom et l’état de la Caméra au-dessus.
8. En tant qu’Administrateur, je veux passer à la Caméra précédente ou suivante par bouton ou par les flèches du clavier.

### Caméras

9. En tant qu’Administrateur, je veux voir toutes mes Caméras dans un tableau lisible, état en pastille + libellé.
10. En tant qu’Administrateur, je veux ouvrir les Réglages d’une Caméra dans un panneau latéral sans perdre la liste, avec des sections que je déplie au besoin.
11. En tant qu’Administrateur, je veux lancer une Détection dans une boîte de dialogue et ajouter une Caméra depuis ses Candidats.
12. En tant qu’Administrateur, je veux confirmer avant de supprimer une Caméra.

### Enregistrement et Relecture

13. En tant qu’Administrateur, je veux voir d’un coup d’œil la place libre (et le seuil), le débit d’écriture et la Conservation, avec un avertissement si le disque ne tiendra pas.
14. En tant qu’Administrateur, je veux régler une Conservation de plusieurs jours (jusqu’à 30), en jours et heures.
15. En tant qu’Administrateur, je veux ouvrir la Relecture depuis le rail, choisir une Caméra et un jour, et voir la Timeline de ce jour.
16. En tant qu’Administrateur, je veux toujours pouvoir ouvrir la Relecture d’une Caméra depuis la page Enregistrement.

### Heure du Site

17. En tant qu’Administrateur, je veux les mêmes réglages et le même tableau de Mise à l’heure qu’en 0.9.1, sous la nouvelle identité.

### Retours

18. En tant qu’Administrateur, je veux un retour clair après chaque action (toast succès / échec) et des erreurs de saisie au bon endroit.
19. En tant qu’Administrateur, je veux des squelettes pendant le chargement et un état vide qui me dit quoi faire.

### Mainteneur

20. En tant que mainteneur, je veux des composants UI réutilisables et des tokens de style centralisés, pour que l’identité ne dérive pas au fil des versions.
21. En tant que mainteneur, je veux que les captures de la doc fonctionnelle montrent la nouvelle interface.

## Implementation Decisions

- **Technique (ADR 0016)** : comme BBASS (`poste/frontend`) : **Tailwind v4** via `@tailwindcss/vite`, **shadcn/ui** (style new-york, composants copiés dans `web/src/components/ui/` : Button, Input, Label, Native Select, Table, Dialog, Alert Dialog, Sheet, Tabs, Switch, Tooltip, Sonner, Collapsible, Card, Alert, Skeleton ; un `<select>` natif stylé plutôt que le Select Radix, un Switch pour les interrupteurs, pastilles d’état faites main plutôt que Badge, pas de case à cocher dans l’UI donc pas de Checkbox) sur **Radix**, icônes **lucide-react**, toasts **sonner**, `clsx` + `tailwind-merge` + `class-variance-authority`, alias `@/`. Tokens de couleur / rayon en variables CSS sur `:root` (`@theme inline`), valeurs de l’identité ci-dessus. **Versions exactes** dans `package.json` (règle ArgOS, pas de `^`). `styles.css` actuel supprimé à la fin.
- **Polices** : Inter et JetBrains Mono en woff2 variables dans `web/src/assets/fonts/` (`@font-face`, licence OFL jointe). Aucun appel réseau externe.
- **Logo** : `web/src/assets/logo-complet.png`, `web/src/assets/logo-tete.png`, `web/public/favicon.png`, produits depuis `docs/img/readme-banniere.jpg` (détourage : noir → blanc, blanc → transparent, rouge conservé).
- **Version** : `VITE_ARGOS_VERSION`, passée au build de l’image `web` depuis `ARGOS_VERSION` (argument de build), `dev` par défaut en local.
- **Routes** : `/connexion`, `/live`, `/enregistrement`, `/relecture`, `/relecture/:idCamera`, `/administration/cameras`, `/administration/heure-du-site` ; `/administration` et `*` redirigent (respectivement vers `/administration/cameras` et `/live`). Coquille = layout de `ZoneConnectee`.
- **Raccourcis Live** : ← / → actifs seulement sur la page Live, ignorés quand le focus est dans un champ.
- **Conservation (ADR 0017)** : `CONSERVATION_MAX = 720` (h) côté API et UI ; `conservation_h` inchangé (pas de migration) ; `recordDeleteAfter` déjà calculé en heures. Saisie jours + heures convertie en heures ; total hors 1–720 refusé (erreur sous le champ). La tenue disque existante s’applique telle quelle.
- **Segments par jour** : `GET /api/cameras/{id}/segments` accepte `?jour=AAAA-MM-JJ` (jour civil dans le fuseau de l’Heure du Site) et ne rend que les Segments fermés qui touchent ce jour, plus la fenêtre de Conservation (`debut`, `fin`) pour griser les jours hors Conservation. Sans `jour` : jour courant. La réponse porte aussi ce qu’il faut pour dessiner le jour sans recalcul côté navigateur : `fuseau`, `jour`, ses bornes `debut_jour` / `fin_jour` (23 ou 25 h aux changements d’heure) et les jours extrêmes `premier_jour` / `dernier_jour`.
- **Toasts** : `<Toaster>` sonner unique dans la coquille (et sur la Connexion si besoin) ; les messages qui étaient en texte inline après une action passent en toast, avec le même texte.
- **Accessibilité** : noms accessibles conservés là où l’élément existe encore (boutons, champs, tableaux `aria-label`) ; panneau et boîte de dialogue ont un rôle `dialog` nommé ; focus visible au rouge de marque.
- **Docs** : ADR 0016 (*Tailwind et shadcn/ui pour l’UI du Site*), ADR 0017 (*Conservation en jours, Relecture à la journée* — remplace la borne 1–24 h de l’ADR 0012 sans la réécrire) ; captures de `docs/features/` refaites ; glossaire inchangé.

## Testing Decisions

Un bon test vérifie un comportement observable (rôles, libellés, routes, réponses de l’API), pas des classes CSS ni une couleur.

- **Filet « mêmes capacités »** : la suite `tests/web/` existante reste la preuve ; elle est réécrite seulement là où le gabarit change (routes, panneau Réglages, boîte de Détection, toasts, page Relecture, rail), en gardant les mêmes scénarios.
- **Coquille** : rail présent sur chaque page connectée, entrée active (`aria-current="page"`), redirection vers `/live` après connexion, pastille de seuil, version affichée, Déconnexion.
- **Live** : Précédente / Suivante et flèches ← / → changent de Caméra ; ignorées dans un champ.
- **Caméras** : Réglages ouverts dans un `dialog` « Réglages de X », appliqués ; Détection dans un `dialog` ; suppression confirmée ; état vide avec action.
- **Enregistrement / API** : Conservation 7 j 0 h acceptée (168 h) ; 30 j acceptés ; 30 j 1 h et 0 j 0 h refusés (API `422` et erreur sous le champ) ; affichage « 7 j ».
- **Relecture / API** : `?jour=` ne rend que les Segments du jour (fuseau du Site, y compris un jour de changement d’heure) ; jour hors Conservation non sélectionnable ; `/relecture` rouvre la dernière Caméra ; une ligne d’Enregistrement ouvre `/relecture/<id>`.
- **Toasts** : résultat d’une action lisible dans un `status`.
- **Tests humains** : parcours complet sur `:staging` (poste fixe + tablette ou fenêtre < 1024 px), captures de chaque écran pour « Ce qu’on peut faire maintenant ».

## Out of Scope

- Nouvelles fonctions métier autres que la Conservation en jours : seek à la seconde, téléchargement d’enregistrements, mosaïque Live, PTZ, IA, VPN, chiffrement des identifiants, postes kiosque.
- Interface mobile (téléphone) : Plus tard.
- Thème clair.
- Timeline zoomable.
- Refonte hors UI : API (hormis borne de Conservation, `?jour=` et `plus_ancien_segment` dans les débits d’écriture, que demande la colonne « Plus ancien Segment » de la page Enregistrement, #159), Compose, install.
- Style du site de documentation (`docs-site/`).
